# Addons zum Herunterladen (#818)

Endnutzer-Sicht: siehe [guide-web-admin.md#addons](guide-web-admin.md#addons) und [guide-discord.md](guide-discord.md) (`/addons`).

Die Gilde lädt die eigenen Addons im Web herunter: **LevelHelper** (`mst1987/levelhelper`, privat), **ProfessionKit** (`mst1987/professionkit`, privat), **AuraKit** (`mst1987/aurakit`, privat), **MacroHelper** (`mst1987/macrohelper`, privat) und **EventHelper Sync** (`mst1987/eventhelper-addon`, öffentlich: Sync-Tool `EventHelperSync.exe` und Addon `EventHelperSync-<version>.zip`). Jedes Addon kommt als GitHub-Release; die Seite zeigt immer das neueste (`/releases/latest`).

## Wer darf was

- **Seite und Download:** Bereich `signup` (die Basisberechtigung jedes Mitglieds, „Profil & Anmeldung“) oder `history` (wer die alte Seite „Sync-Tool & Addon“ öffnen durfte). Ohne Login 401, ohne einen der beiden Bereiche 403 — der Download ist ein normaler `GET` mit der Sitzung, also ein `<a href download>`.
- **Nur Orga:** Ein Addon mit `orgaOnly: true` (Schalter „Nur Orga“ in Einstellungen → Module → Addons; Standard nur beim EventHelper Sync) ist nur für `userIsOrga` da (Voll-Admin oder Orga-Rolle, [permissions.md](permissions.md), „Orga-Rollen und Orga-Bereiche“). Für alle anderen fehlt die Karte in `GET /api/addons` (auch in `addonVersions`), `GET /api/addons/download` antwortet 403 `orga_only` — vor dem Download-Limit und bevor GitHub gefragt wird, mit einer Warnzeile im Log. `/addons` blendet es für Nicht-Orga aus (Orga-Prüfung über `userAccess.resolveAccess`; schlägt sie fehl, gilt das Basisrecht, also nicht Orga). Die Karte der Orga trägt `orgaOnly: true` und auf der Seite den Chip „Orga“. Ein gespeicherter Eintrag ohne das Feld übernimmt den Standard des Eintrags mit derselben `id` (sonst `false`), ein ausdrückliches `true`/`false` gilt immer.
- **Admin-Hinweise:** nur Voll-Admins bekommen `repo`, `private` und `tokenSet` in der Antwort und sehen auf der Karte, dass der Token fehlt oder abgelehnt wird; alle anderen lesen nur „Gerade nicht verfügbar“.
- **Einstellungen:** `github` steht in `CREDENTIAL_KEYS`, `addonDownloads` in `ADDON_KEYS` (`apiRoutes/settings.js`) — beide nur für Voll-Admins (`FULL_ADMIN_KEYS`). `publicConfig()` macht aus dem Token `{ hasToken }`; `PATCH { github: { token } }` folgt dem Vertrag der anderen Geheimnisse (weglassen = behalten, `""` = löschen). Die Karte „GitHub (Addons)“ unter Verbindungen ist der Ort dafür; ohne Token zählt sie als „nicht eingerichtet“.

## Die Addon-Liste wird nie aus Versehen leer

- **Nur eine Bearbeitung ersetzt sie.** `PATCH /api/settings` nimmt `addonDownloads` nur **allein** an (`addonListPatch()` in `apiRoutes/settings.js`): neben irgendeiner anderen Einstellung ist es 400 `invalid_addons`, ebenso eine Liste, von der der Normalisierer nichts übrig lässt. Fehlt das Feld, bleibt die Liste, wie sie ist (der Token-Save schickt nur `{ github: { token } }`). Eine angenommene Liste setzt `addonDownloadsCustomized: true`.
- **Der Store verlangt das Kennzeichen.** `saveConfig()` ersetzt die Liste nur, wenn `addonDownloadsCustomized` mitkommt; eine mitgeschleppte Liste ohne es wird ignoriert.
- **Selbstheilung.** `storedAddonList()` (`addonConfig.js`): nie gespeichert = Standardliste; eine **leere** Liste gilt nur mit `addonDownloadsCustomized: true` (ein Admin hat das letzte Addon entfernt), sonst liest sie sich wieder als die Standardliste. Einzelne Addons entfernen bleibt möglich.
- **„Standard wiederherstellen“** (Einstellungen → Module → Addons, mit Rückfrage) schickt `{ addonDownloadsReset: true }`: der Server schreibt `defaultAddons()` und löscht das Kennzeichen.

## Leere Seite gibt es nicht

- Keine Addons für die Version: „Für <Version> gibt es hier keine Addons.“, dazu die Versionen, die welche haben (`addonVersions` der Antwort, z. B. auf Classic), und für Voll-Admins der Knopf „Addons einrichten“ (`/settings?section=addons`).
- Fehler der Anfrage: Meldung mit „Erneut versuchen“ (`useApi().reload`).
- **Klassen nie mit `ad-` beginnen.** Die Seite hieß zuerst `ad-grid`/`ad-card`; EasyList (Standardliste von uBlock Origin, AdBlock Plus, Brave …) blendet genau `.ad-card` und `.ad-grid` aus. Mit Werbeblocker blieben Kopf und Fußzeile, alle Karten fehlten ohne jede Meldung. Das Präfix ist jetzt `dlp-` (download page); `test/web-client/conventions/adBlockClasses.test.js` verbietet `ad-`, `ads-`, `advert…`, `sponsor…` im ganzen Client.

## Download über den Server

`resolveDownload()` sucht im (gecachten) neuesten Release die Datei mit genau dem Namen **und** passendem Muster des Addons; sonst 404 (`unknown_addon`, `unknown_asset`, `no_release`) bzw. 503 (`unavailable`: Token fehlt, GitHub nicht erreichbar). Danach zählt das Limit (429 mit `Retry-After`), dann streamt die Route GitHubs Antwort mit `Content-Type` nach Endung (`application/zip`, `application/vnd.microsoft.portable-executable`, sonst `application/octet-stream`), `Content-Disposition: attachment` mit Dateinamen (ASCII und RFC 5987), `Content-Length` und `Cache-Control: private, no-store`. Bricht der Browser ab, wird der Stream zu GitHub geschlossen. Die Komprimierung (`compression.js`) lässt Streams in Ruhe.

**Protokoll:** jede Datei als Zeile `[info] [addons] download <id> <version> <datei> by <Name> (<Discord-Id>)` (pm2-Log), abgelehnte und fehlgeschlagene als `warn`. Der Token steht nie in einer Zeile: geloggt werden nur Kurzcode und Status, nie ein axios-Fehlerobjekt (das trüge die Request-Header).

## Version zuerst

Die Seite schickt die Version des Content-Umschalters (`?version=`), der Server löst sie über `resolveVersionQuery()` auf (nichts = Hauptversion, „Andere Versionen ausblenden“ = immer die Hauptversion) und zeigt nur Addons, deren `versions` sie enthalten. `/addons` nimmt die Version des Befehls (`versionOfCommand`: Option, sonst Kategorie des Kanals, sonst Hauptversion). Die Seite ist deshalb nicht mehr `neutral` in `menu.json`.

## Detailseite `/addon/<id>`

Design: „Addon-Detailseite“ (fünf Boards, Okt 2026). Ziel des Discord-Links „Patchnotes“ und des Knopfs „Alle Patchnotes“ unter der Notizbox jeder Karte (die Box selbst zeigt nur noch die ersten 200 px, ausgeblendet statt gescrollt).

- **Unabhängig von der Spielversion.** Die Seite fragt `GET /api/addons/detail?addon=<id>` (gleiche Bereiche und „Nur Orga“-Regel wie `/api/addons`) und zeigt das Addon, egal welche Version das Menü zeigt. Sie ist versionsneutral: Brand-Akzent, kein Versions-Schalter (`lib/app/menu.ts` `isNeutralPage`, die Ausnahme unter dem nicht neutralen Eintrag „Addons“; `test/web-client/conventions/contentVersion.test.js` `NEUTRAL_PAGES`). Die Spielversion(en) des Addons stehen als eckiges Badge in ihrer Versionsfarbe. Bewusst auch bei „Andere Versionen ausblenden“: die Detailseite zeigt dann trotzdem ein Addon einer anderen Version, damit ein Discord-Link nie ins Leere führt (die Liste `/addon` bleibt bei der Hauptversion).
- **Aufbau:** Kopf (Icon, Kicker, Badge, Titel einzeilig, Beschreibung, „Alle Addons“, Download-Knöpfe wie auf der Karte), Meta-Zeile (Version, Datum, Spiel; bewusst kein „/reload reicht“: das stimmt nicht immer und steht, wenn es gilt, in den Notizen selbst), Patchnotes groß, Installation, Download-Limit. Krümel „Menü / Addons / <Name>“ (`usePageCrumb`).
- **Notizen sicher:** `noteGroups()` macht aus dem Markdown Gruppen (`#`–`######` = Gruppenkopf; Neu/New, Verbessert/Improved, Behoben/Fixed bekommen ihre Farbe, alles andere das graue Quadrat), Listen, Absätze, `**fett**` und `` `code` ``; Zitate und Kursiv als reiner Text, Links nur als ihr Text, nie HTML, nie `dangerouslySetInnerHTML`. GitHubs Block „## What's Changed“ samt allem darunter und jede „**Full Changelog**“-Zeile fallen weg (`ownNotes()`, auch für den Klartext der Karte).
- **Installation:** der Zip-Ordner der Menü-Version, wenn das Addon für sie ist; sonst die Ordner aller seiner Versionen („… (WoW TBC) oder … (WoW Forever)“).
- **Zustände:** unbekannte, ausgeschaltete oder (ohne Orga-Recht) „Nur Orga“-ID: dieselbe Meldung mit „Alle Addons“ (die Adresse verrät nichts); kein Release: der Kopf bleibt, Download, Patchnotes und Installation fehlen ganz; GitHub-Fehler ohne gemerkten Stand wie auf der Karte.
- **Login mit Rückkehr:** ohne Sitzung verlinkt der Hinweis `/auth/login?returnTo=<Pfad>`; auf `/addon/<id>` steht dazu „Danach: <Icon> <Name> · Patchnotes“. Name und Icon kommen aus `GET /api/addons/name?addon=<id>`, der einzigen Addon-Route ohne Login (`auth: "none"`): nur `id`, `name`, `icon` eines eingeschalteten, nicht „Nur Orga“-Addons, aus der Einstellung, ohne GitHub-Abruf und ohne Release-Daten; unbekannt, aus oder „Nur Orga“ ist 404 `unknown_addon`. Ohne Antwort zeigt der Hinweis den Namen aus der ID; ein alter Link `/addon#addon-<id>` bekommt dieselbe Zeile. Der Server (`pageRoutes.js` `safeReturnPath`) nimmt nur einen Pfad dieser Seite: beginnt mit genau einem `/`, kein `\`, nur druckbares ASCII (keine Steuer- oder Leerzeichen, nichts über 0x7e, sonst würfe `writeHead`), nicht unter `/auth`, `/admin` oder `/admin2` (die leiten erneut um) — geprüft roh **und** einmal dekodiert, weil `server.js` den Pfad vor dem Routing dekodiert; sonst Startseite. Auch die alten Mounts `/admin`/`/admin2` (`legacyMount`) schicken ihr Ziel durch `safeReturnPath` (vorher wurde `/admin//evil.example` zu `//evil.example`, ein fremder Host). Ein abgelaufener OAuth-State (10 Minuten) meldet noch an, sein Rücksprung zählt aber nicht mehr; abgelaufene States werden beim nächsten Login weggeräumt. `?next=/p/<token>` des Raidplans gilt weiter und hat Vorrang.

| Wo | Was |

| `src/commands/lookup/addonCenterButton.js` | `componentRoute` für `addonhub:` (Zugriff wie `/addons`, ohne Event-Server-Prüfung, die Zentrale darf auf dem Talk-Server stehen). |
| `src/stores/addonCenterStore.js` | `settings/addon-center.json`: Einstellungen, gepostete Nachricht, bekannte Versionen ([data-storage.md](data-storage.md)). |
| `src/web/apiRoutes/addonCenter.js` | `GET/PUT/POST/DELETE /api/addon-center`, nur Voll-Admins (`adminOnly` + `full`). |
| `src/web-client/src/pages/settings/AddonCenterCard.tsx` | Der Block „Downloadzentrale im Discord“ unter der Addon-Liste (`api/addonCenter.ts`). |
| `src/config/botText/de/addons.js` | Die deutschen Texte (`tr()`; die Zentrale und die Meldung in der Server-Sprache, die ephemeren Antworten in der Sprache des Klickenden). |

- **Eine Nachricht, Components V2.** Kopf-Container (Akzent `#8a7cff`): „## Addon-Downloadzentrale“ und die Anleitung (kein Abo-Knopf). Je Addon ein Container in seiner Farbe (`ADDON_COLORS`: LevelHelper `#60a5fa`, ProfessionKit `#fbbf24`, AuraKit `#c084fc`, MacroHelper `#2dd4bf`, EventHelper Sync `#8a7cff`; ein weiteres Addon bekommt fest nach seiner `id` eine Farbe aus `FALLBACK_COLORS`, kein neues Konfig-Feld): „### <App-Emoji> Name `NEU`“, Kurzbeschreibung, „-# Version 0.3.0 · 12.10.2026 · [Patchnotes](<Web>/addon/<id>)“ (Markdown-Link in der Unterzeile, kostet keine Komponente; nur mit Release) und „Herunterladen“ (📥, Success, `addonhub:dl:<id>`). Ohne Release, ohne passende Datei oder bei einem GitHub-Fehler steht statt des Knopfs ein kurzer Hinweis in der Unterzeile; die Nachricht scheitert nie an einem Addon. **Patchnotes:** die Repos sind privat, ein github.com-Link wäre für Mitglieder ein 404. Der Link führt deshalb auf die Detailseite des Addons (`/addon/<id>`, `publicBaseUrl()`), die es unabhängig von der Spielversion des Menüs zeigt. Ältere Links (`/addon#addon-<id>`) leitet die Seite „Addons“ dorthin weiter. Lesen darf jeder mit Bereich `signup` oder `history`, also jedes Mitglied mit Login (ob jemand ohne Bot-Login das Web öffnen kann, hängt an der Anmeldung per Discord).
- **Welche Addons:** `enabled`, nicht `orgaOnly`, und `versions` enthält die Spielversion der Zentrale. **Spielversion:** die Einstellung `versionId` (Store; `""` = automatisch) gilt, solange sie eine bekannte und sichtbare Version ist (`knownVersion`, `isVersionVisible`); sonst, und bei „Automatisch“, die Version der Kategorie des Kanals (`categoryIdOfChannel` und `mainVersionFor`, eine ausgeblendete Version fällt wie bei `/addons` auf die Hauptversion zurück). `channelVersion()` ist die eine Stelle dafür; Zentrale, Versionsprüfung und Job nutzen sie. Eine andere Spielversion zeichnet eine gepostete Zentrale sofort neu und merkt sich die Versionen der nun gezeigten Addons nur (`rememberVersions`), ohne Update-Meldung. Hat die Spielversion keine Addons, nennt die Zentrale sie: „Für <Version> gibt es hier keine Addons.“ `GET /api/addon-center` liefert `versions` (wählbare: id + label) und `autoVersion` (die Version, die „Automatisch“ für den gewählten Kanal ergibt, `null` ohne Kanal); `PUT` nimmt `versionId` (`""` oder bekannte ID, sonst 400).
- **App-Emojis:** `eh_addon_<id>` (`appEmojis.addonEmojiName`); der Katalog lädt das WoW-Icon jedes **Standard**-Addons hoch. Ein später angelegtes Addon steht ohne Emoji da.
- **Discord-Grenzen:** 40 Komponenten je Nachricht (Kopf 2 oder 4, Addon 4 bzw. 2 ohne Knopf). Was nicht passt, fällt weg, der Kopf sagt „N weitere Addons stehen auf der Download-Seite.“, das Log warnt. Die Kurzbeschreibungen teilen sich, was von den 4000 Zeichen übrig ist.
- **Bearbeiten statt neu posten.** Die Zentrale merkt sich einen Fingerabdruck (`hash`) und wird nur bei einer Änderung bearbeitet; ist die Nachricht weg (linkWatch meldet das Löschen sofort, sonst findet es die nächste Prüfung), wird sie neu gepostet. Nachrichten-ID im Store, also nach einem Neustart weiter. Bot offline: der Job tut nichts.
- **Job** (`addonCenter`, erste Runde 1 Minute nach dem Start, dann alle **15 Minuten**, nutzt den Release-Cache): je Addon der Zentrale die neueste Version gegen die bekannte (`seen`). Unbekannt (erster Lauf, neues Addon, frisch gepostete Zentrale) → nur merken. Neuer → `newSince` (NEU sieben Tage) und Neuzeichnen der Zentrale. **Update-Ping:** ist eine Rolle gesetzt (`roleId`, kein Schalter dafür) und `checkVersions()` findet für die Spielversion der Zentrale eine höhere Version, postet der Bot EINE kurze Textnachricht in den Kanal der Zentrale (`discord.postRolePing`, Klartext mit `<@&Rolle>` im `content`, `allowedMentions` nur diese Rolle, Link-Vorschauen aus): „<@&Rolle> **LevelHelper 0.5.0** ([Patchnotes](<Web>/addon/levelhelper)) ist da.“ bzw. „… Neue Versionen: **A 1** (…) · **B 2** (…)“ – alle in einer Prüfung aktualisierten Addons in einer Nachricht, keine Patchnotes im Text (Nutzerwunsch Okt 2026, die Repos sind privat). Kein Ping ohne Rolle, für nur gemerkte Versionen (erster Lauf, neues Addon, andere Spielversion) und für eine ältere „latest“. **Aufräumen:** der Ping steht im Store (`ping: { channelId, messageId, postedAt }`, überlebt Neustarts); vor einem neuen wird der alte gelöscht, und jede Runde des Jobs (auch ohne gepostete Zentrale) löscht ihn `PING_TTL_MS` = 12 Stunden nach dem Posten. Ist die Nachricht schon weg, wird der Eintrag trotzdem geleert; ein Fehler beim Posten steht nur im Log. Der alte Schlüssel `announce` im Store hat keine Wirkung. Eine ältere „latest“ (zurückgezogenes Release) wird still übernommen.
- **Download per Klick** (`addonCenterBot.download`): sofort ephemer deferren; Rechte wie im Web (`signup` oder `history` über `userAccess.resolveAccess`, `orgaOnly` nur Orga, abgelehnt vor GitHub), dann `resolveDownload()`, die Größe gegen das Upload-Limit (`interaction.attachmentSizeLimit`, sonst Boost-Stufe 2/3 = 50/100 MB, sonst 10 MB), das gemeinsame Limit aus `downloadLimit.js` (zählt Web und Discord zusammen je Discord-Konto), dann `openAssetStream()` in den Speicher (bricht über dem Limit ab) und als Anhang: TextDisplay plus File-Komponente `attachment://<Datei>`. Mehrere passende Dateien → erst eine ephemere Auswahl (`addonhub:file:<id>:<assetId>`). Texte genau wie Board 2; die Uhrzeit beim Limit in `Europe/Berlin`. Log: `download <id> <version> <datei> by <Name> (<Discord-Id>) via discord`, Ablehnungen als `warn`; nur Kurzcode und Status, nie ein Fehlerobjekt (der Token steckt in dessen Headern).
- **Einstellungen** (`AddonCenterCard`, nur Voll-Admins): Kanal (Kanäle aller konfigurierten Server, hinter dem Namen die Spielversion seiner Kategorie), Rolle für Update-Pings (Rollen des Servers des Kanals; ein Kanal auf einem anderen Server leert sie), Spielversion („Automatisch (<Version der Kategorie>)“ oder eine feste), Posten/Neu posten, Stand, Ansehen, Entfernen. Jede Änderung geht sofort an `PUT /api/addon-center`, nie an `PATCH /api/settings`: die Regeln „Die Addon-Liste wird nie aus Versehen leer“ bleiben unberührt. Ein Kanalwechsel löscht die alte Zentrale und postet im neuen Kanal; scheitert das, bleibt die alte stehen und die Antwort trägt `warning`.
- **Nur live prüfbar:** ephemere Anhänge mit File-Komponente, das echte Upload-Limit des Servers.

## Einrichten: GitHub-Token

Fine-grained Personal Access Token auf github.com (Settings → Developer settings → Personal access tokens → Fine-grained tokens): Resource owner `mst1987`, Repository access „Only select repositories“ mit `levelhelper`, `professionkit`, `aurakit`, `macrohelper` (und optional `eventhelper-addon`), Permissions → Repository permissions → **Contents: Read-only** (Metadata: Read-only kommt automatisch), sonst nichts. Ablaufdatum setzen und den Token unter Einstellungen → Verbindungen → GitHub (Addons) eintragen. Ein abgelaufener Token zeigt Admins „GitHub lehnt den Token ab“.
