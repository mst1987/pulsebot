# Kanäle (`channels` area)

Endnutzer-Sicht: siehe [guide-web-admin.md#kanäle](guide-web-admin.md#kanäle).

The server's channels as Discord's sidebar (issue #259): `pages/ChannelsPage.tsx` is **one list** (`components/channels/ChannelTree.tsx`: categories fold, one line per channel with check box, type, name large in mono, status only as badge *Event* / *vergangen*) full width, with the counts in the tabs (*Kanäle · n*, *Archiv · n*) and the purposes as **one slim strip** above the list (*Zwecke* + badges *n fehlt* / *n Warnungen* — "gesetzt" only when nothing needs attention —, *Vergangene Events n* with the verb button *Auswählen*, and *Zwecke zuweisen*, which opens the purposes dialog). The former side panel with big figures is gone. Everything else about a channel — event, topic, purposes, slowmode, rights — is its **tooltip** (`channelTip()` in `lib/discord/channels.ts`); the purposes table (what the bot uses a channel for, still settings) opens as a dialog (`PurposeList.tsx`). Don't put it back on the page.

- **Threads nest under their channel, three levels deep (#361).** Discord gives a thread's `parentId` the id of the *text channel* it hangs off, not a category — `discord.listAllChannels()` marks it (`isThread`, `THREAD_TYPES` = announcement/public/private thread) so `groupByCategory()` (`lib/discord/channels.ts`) can resolve its real category through that channel instead of dropping it into "Ohne Kategorie": each `ChannelNode` in a group carries its own `threads: Channel[]`, and only a thread whose parent channel is not in the list at all (filtered out, deleted) still falls back to a loose row of its own. `ChannelTree.tsx` renders a thread's row right below its channel, indented (`kn-row-thread`) and folded per channel (`kn-fold-sm`, open by default, always open while searching); selecting a whole category selects its channels' threads too. A thread only offers **rename and delete** — moving it into another category or duplicating it does not apply, so *Bearbeiten* and *Duplizieren* stay hidden on its row.

- **Row actions are visible, never hidden behind a gesture.** On hover and keyboard focus a row shows *Umbenennen* and *Archivieren* (not on a thread) and a *…* menu (`MoreMenu.tsx`: *Bearbeiten*, *Duplizieren*, *Löschen*). On touch screens and narrow widths (`hover: none` / ≤ 760 px) the buttons are hidden and the *…* menu is always visible and carries *Umbenennen* / *Archivieren* too (`kn-touch-only`).
- **Inline rename**: the *Umbenennen* button, F2 or a double click (a shortcut only), Enter saves, Esc/blur discards. Discord's name rules apply while typing — `src/utils/channelNames.js` is the tested source, `lib/discord/channelNames.ts` its twin (regex and body held identical by `test/utils/channelNames.test.js`; `schemaName()` in `lib/raids/eventPlan.ts` inlines the same regex). **The rules are Discord's own (#285):** lower case, whitespace → `-`, doubled dashes collapsed, and only ASCII punctuation except `-`/`_` (plus control characters) is removed — emojis and Unicode symbols (`・ │ ┃ 【】 ⚔`) **stay**, so `🔥・mi-16-09-ssc-tk` keeps its design; `.` is stripped, so `16.09` is stored as `1609`. Don't go back to a letters-digits-only whitelist.
- **New event channels look like the previous ones (#285, `src/services/discord/channelNaming.js`).** One answer for `/event anlegen` (new and duplicate), the web's create dialog, quick-create, *Umbenennen nach Schema* with an empty schema and `/kanal anlegen` without a name: `deriveChannelName({ guildId, categoryId, date, instanceIds | raid, fromEventId })` → `{ name, source: "previous" | "schema" | "default", label, detail, design, fromChannel, replaced: [{ part, from, to }], templateChannelId, placement }`; the pure halves are `namingContext()` / `nameFor()` / `describeResult()` (events from `loadEventGroups` with the lookback window, live channels, `channelArchiveStore` schemas — every read best-effort). Order: a **stored own schema** of the category wins (the default schema stored by quick-create's "merken" does *not* count as one); else the **latest event channel of the category** (the one with the same raid tag first; for a duplicate the chosen event's channel), taken apart by `derivePatternFromName()` in `utils/channelNames.js` — **only tokens equal to that event's own Berlin day** are replaced (`dd-mm`, `dd_mm`, `ddmm`, `dd-mm-yy(yy)`, `yyyy-mm-dd`, `d-m`, weekday de/en short/long) and the raid only where the event's instance tag (`ssc-tk`, `ssctk`, `ssc_tk`, ids, the stored raid) stands as a whole word; a name without a recognisable date falls to the **default schema with the channel's symbol prefix** (`prefixOf`). Anything else in the name — `t6`, `25er`, emojis, separators, order — is never touched, and a missing new raid keeps the old one. **Design:** the new channel is a *copy* (`discordChannels.createFromTemplate`) of the stored template channel, else of that latest event channel (a duplicate always copies its source); only a category without any event channel gets a plain channel with the category's rights. **Position:** `placementFor(eventChannels, day)` → right after the channel of the latest date ≤ the new day, else before the next one; `discordChannels.placeChannel()` / `positionTarget()` do the `setPosition` (best-effort, never fails the create; a series sorts each new channel behind the one it just made). **Visible:** the bot's step 1 says `neu wie #… — Wochentag, Datum und Raid werden ersetzt` and the confirmation `Name: \`…\` · abgeleitet aus #… (Datum 16-09 → 23-09)` plus the design line; the web shows one `components/channels/NamingBadge.tsx` (label on the badge, `detail · design` in its tooltip; `short` per row in the bulk rename) — under the name field of `RaidCreateDialog` (suggestion from `GET /api/raids/channel-name`, area `raids`; a hand-typed name reads "von Hand benannt"), above the quick-create preview (`naming` in the batch answer; empty schema = derived, `templateChannelId` empty = copy of the derived channel) and per row in the rename preview (empty schema = derived; with nothing to derive from, the name stays). `createEvent` answers with `channelNaming`. Tests: `test/utils/channelNameDerivation.test.js`, `test/services/discord/channelNaming.test.js`, `src/web-client/src/components/channels/__tests__/NamingBadge.test.tsx`.
- **A category's naming schema has its own place**: the pencil on the category head (`ChannelTree.tsx`, hover like the row icons, only `channels` write) opens `components/channels/CategorySchemaDialog.tsx` — schema with the placeholder chips, raid and template channel folded under *Raid & Vorlage*, and the next three weekly names as preview (quick-create's dry run with `ignoreStoredSchema: true`, so an empty field previews the *derived* names, not the schema stored so far). Saving goes to `POST /api/channels/schema` (`saveSchema` in `apiRoutes/channels.js`: category of this guild, ≤ 200 characters, must render to a name, template channel of this guild) → `channelArchiveStore.saveCategorySchema`; an empty schema means "wie der letzte Event-Kanal" again, the remembered event time stays. A category with an own schema carries a small *Schema* badge (schema in its tooltip; `ownSchemaOf()` in `lib/discord/channels.ts` — the default schema an old quick-create stored does not count). Quick-create's "merken" still stores too.
- **A category's name is never part of a channel name (#744).** Deriving, the schema (`{tag}`, `{dd}`, `{raid}`, `{name}` = the channel's own previous name, …) and the stored schemas all key on the category **id** and the previous channel; there is no placeholder for the category name. Renaming a category in Discord therefore renames no channel and, since quick-create skips every name that exists, makes none twice (`test/services/discord/channelNaming.test.js`). The raids of a closed section keep the category's old name in the lists (docs/events.md, "Kategorien umbenennen, deaktivieren, abschließen").
- **Emoji picker beside the name** (`components/ui/overlay/EmojiPicker.tsx`, wrapped by `components/channels/ChannelEmojiPicker.tsx`): in the create dialog's channel step (`KanalStep.tsx`), the edit dialog, quick-create's schema field and the category schema dialog. Discord-like — search (German or English CLDR names), one tab per section, grid with arrow keys (nine to a row), the hovered emoji named in the footer. First rows: *Passt zu <Raid>* (`lib/raids/raidEmojis.ts`, a fixed list per instance id; a tag or channel name is read with `instanceIdsOfTag`, a Forever instance borrows its namesake's row), *In dieser Kategorie* (the leading emojis of the category's channels, most used first), *Zuletzt benutzt* (`localStorage`, per browser). A pick **replaces the emoji the name starts with** and keeps its separator; a name without one gets emoji + the category's separator (`setLeadEmoji` / `emojiStyleOf` in `lib/discord/emoji.ts`, default `・`). An empty schema field starts from the default schema, so a pick never turns "like the last event channel" into a bare emoji. The data is `emojibase-data` (MIT), loaded per language only when a picker opens (~100 KB gzip); only Emoji ≤ 12.1 and no country flags, because the menu draws with the system font and Windows 10 stops there. `/event anlegen` offers the same picks as a select ("Kanal-Icon", backend twin `utils/leadEmoji.js` + `config/raidEmojis.js`, see docs/events.md). Deriving a name (`channelNaming.js`) still leaves emojis untouched — a new raid in a category inherits the previous channel's emoji until it is swapped here.
- **`{mon}` — the month in three English letters** (`jan feb mar apr may jun jul aug sep oct nov dec`, `MONTHS` in `utils/channelNames.js`; `schemaName()` in `lib/raids/eventPlan.ts` has the same list). Deriving recognises it too: `dd-mon`, `d-mon`, `mon-dd`, `dd-mon-yy(yy)`, with `-`, `_` or no separator. A date's edges are checked by kind (`dateEdge`): digits must not run on into digits, the month's letters not into letters — `16-sept` is no date.
- **Selection → bulk bar** (`ChannelBulk.tsx`, sticky at the bottom of the list: *n ausgewählt* · *Mehr ▾* · *Archivieren* · *Löschen* · *Auswahl aufheben*): *Mehr* holds *Kategorie … / Thema …* (one dialog where every field starts at "unverändert" and only changed fields are sent, `bulkChanges()`) and *Umbenennen nach Schema …* previews on the server (`POST /api/channels/rename-preview`, date from the channel's event). Changes go **one channel per request with a pause** (`runInSteps()`, progress in the job toast) because Discord bounces bursts; the server's `channelOps.runSerial()` pauses between channels too and answers per channel (`"3 Kanäle geändert, 1 fehlgeschlagen: fehlende Rechte"`).
- **Archive, never auto-delete**: *Archivieren* moves into the archive category and denies writing to every overwrite plus @everyone (the bot keeps its own); `channelArchiveStore.js` (`data/settings/channel-archive.json`) logs who/when and holds the archive category per server, the hint deadline (`archiveDeleteHintDays`, default 14) and the quick-create schema per category — kept out of the general config so `channels` write is enough. **Deleting** always needs the name typed (several: `LÖSCHEN`, checked again on the server). From the **Archiv tab** `discordChannels.deleteChannel()` refuses any channel outside the archive category, whatever the caller sent. From the **channel list** (trash icon per row, *Löschen …* in the bulk bar beside *Archivieren*) the request carries `anywhere: true` — any channel may go, also without an archive category, but never a category (`fetchChannel` hands none out); the dialog first names every channel of an **upcoming** event whose signup message goes with it (`deleteWarnings()` in `lib/discord/channels.ts`). Archiving stays the suggested way for anything that may be needed again. The waiting count shows on the page and as the dashboard task `channels` (`buildTasks`, yellow past the deadline, only for users who can read `channels`).
- **Quick-create** (`QuickCreateDialog.tsx`, `POST /api/channels/batch`): schema empty (= like the previous event channel, see above) or typed (`{tag}-{dd}-{mm}-{raid}`, placeholders in `PLACEHOLDERS`), once or weekly × n, optional template channel (clone: rights, topic, slowmode; empty = copy of the derived channel); `dryRun` answers the plan with `exists`, existing names are skipped, never duplicated. Drag & drop between categories is deliberately not built.
- **"Gleich Event anlegen"** (quick-create, only with a category and for `raids` write — `canCreateEvents` in `GET /api/channels`, checked again on the server): one switch and one time field in the dialog, the category's default raid template and source as one small badge with the details in its tooltip (`eventDefaults` per category: `categoryRaidTemplate` + `categorySignupSource`). `POST /api/channels/batch` with `withEvent: true, time` creates each channel and then an event in it through `eventCreate.createEvent()` (date from the series, title = template name, else category name, `raidTemplateId` of the category default, `signupSource` of the category). A failed event leaves its channel; the result carries `eventId` / `eventError` per channel and `message` lists every channel whose event failed, one per line (`.toast-msg` keeps line breaks). The time is remembered with the schema (`schemas[cat].time`).
- **A deleted event channel (#537).** An own upcoming, not cancelled raid whose channel is gone (`linkCheck`, see "Links in overviews" in docs/discord-servers.md) is the dashboard task **"Kanal von <Event> fehlt"** (`missingChannelTasks` in `dashboardOverview.js`, from `loadMissingChannels` in `dashboardData.js`, for `raids` read; the button only for `raids` write). **"Kanal neu anlegen"** = `POST /api/raids/manage/recreate-channel { event }` (area `raids`, CSRF) → `eventManage.recreateChannel()`: refused while the channel exists (409 `channel_exists`) or nothing is known (503 `bot_offline`); name from `channelNaming.deriveChannelName` (like the category's previous event channels, `excludeChannelId` = the dead one; else the stored name), `discordChannels.createFromTemplate` in the event's category (a copy of the template/previous channel, else the category's rights — the same as quick-create), placed by date. Then the event carries the new channel, `message` is cleared and `refreshEventMessage` posts the signup message, a posted setup is posted again, the raid plan post record is dropped, the Discord event and the overviews follow, the log says "Kanal neu angelegt". A category that is gone too puts the channel at the top level and says so in `warnings`.
- **Discord tabs (`components/channels/DiscordTabs.tsx`).** *System › Discord* is one tab row instead of a side menu: *Übersicht* (`/channels/overview`, the menu entry *Discord* lands there), *Kanäle* (`/channels`), *Rollen* (`/channels/server-roles`), *Mitglieder* (`/channels/members`), *Rollen-Nachrichten* (`/channels/roles`), taken from `menuFamily("channels")` (`config/menu.json`), each with its count from `GET /api/discord/tab-counts?guildId=` (area `channels`; channels without threads, roles without @everyone, members without bots — the same people the member list shows with *Bots ausblenden* on —, role messages). **Phone (≤ 600 px):** the row scrolls inside itself, never the page; the tabs drop their counts and *Rollen-Nachrichten* shows its short word (`tabs.short.roleMessages`: *Nachrichten* / *Messages* — the full name stays the accessible name and the tooltip), so all five fit at 390 px; should the row still be wider than the screen, the active tab is scrolled into view on load and on every tab change (`scrollToShow()` in `lib/discord/tabs.ts`, only the bar's `scrollLeft`, never the page) and a plain chevron button (solid background, hairline, no fade) at each cut-off edge scrolls on. Add a new Discord page as a sub entry there, not as a second navigation.
- **Server picker (`components/channels/ServerPicker.tsx`, #895).** Overview, roles, members and the role-message editor work on one server of the server list (`discordServers.servers`, docs/discord-servers.md), read from `GET /api/discord/servers` (area `channels` read; `{ guildId, name, label, online, iconUrl }`, kept for the session by `useServerPick()` in `hooks/useServerPick.ts`; when the list fails, `pick.error` carries the message and a page says so instead of calling the bot offline). The pick is `?guild=<id>` in the URL — none for the first server, an old `?side=talk` link opens the first server (#897, `lib/discord/serverPick.ts`); every API call sends `guildId`, an id outside the list is answered 400 `unknown_guild` (`src/web/http/serverQuery.js`). Hidden with one server, a segment with the Discord names up to three, a select beyond that (with label and *Bot nicht da*). Switching drops the old server's open role or member from the URL.
- **Übersicht (`pages/channels/DiscordOverviewPage.tsx`, display only).** The start page of the Discord area, from `GET /api/discord/overview?guildId=` (data and API: docs/discord-servers.md „Discord-Übersicht“); the words and links come from `lib/discord/overview.ts`, the page only renders. Server picker and *Neu prüfen* on top. **One main element, *Braucht Aufmerksamkeit*:** one line per point with a status word in its meaning colour (*fehlt* / *gelöscht* red, *Hinweis* / *kein Zugriff* orange, *Aufräumen* neutral), what it is about, why, and one button to where it is fixed — a missing function right jumps to the bot check on the page (*Recht prüfen*), a channel to `/channels`, a role above the bot or empty roles to `/channels/server-roles`, a gone message to where it is posted again (`MESSAGE_HOME`). A link the account may not open (`mayOpenHref`, the menu entry the path lies under) is left out, the point stays. Nothing open = *Alles in Ordnung*; below it one calm line of role hygiene in words („40 Rollen · 3 ohne Mitglieder · 1 mit heiklen Rechten“, parts the bot cannot count left out). Then side by side (one column ≤ 900 px): *Neu und gegangen* (7 days, eight lines then *Alle N zeigen*; the name links to `/channels/members?user=<id>`, with the open rosters or the character count beside it) and *Feste Bot-Nachrichten* (sortable table: kind, channel, status, the open-in-Discord icon only for a message that stands). Last the **bot check**: one row per function with the rights it needs and its state on the picked server (one column; each server checks only what is set up there), sorted by state with the missing rights first, the missing ones named under *fehlt*. **Neu prüfen** reloads with `fresh=1` — every fixed message is asked again, so the button waits 30 s between two presses on the same server (`refreshWait`, countdown on the button; each server keeps its own wait). States of their own: bot offline (badge in the head and one sentence instead of the sections, button off), server not set up (the roles page's sentence). Tests: `lib/discord/__tests__/overview.test.ts`, `DiscordOverviewPage.test.tsx`.
- **Rollen (`pages/channels/ServerRolesPage.tsx`, display only).** Every role of the picked server as Discord orders it, from `GET /api/discord/roles?guildId=` (`src/services/discord/serverRoles.js` → `apiRoutes/discordRoles.js`, area `channels` read): colour dot and name in the role colour, rank (1 = top, @everyone none), *N Mitglieder* (from the member cache; `membersError` when the GuildMembers fetch failed), what the role means for the bot (`uses`: orga, bot commands, web rights, category raider, roster, role sync, role message, addon ping, the bot's own role — words in `lib/discord/serverRoles.ts`), sensitive permissions (the one list `SENSITIVE` of `services/discord/roleHygiene.js`, so the Discord overview counts the same roles; the client copy in `lib/discord/permissions.ts` is kept equal by `serverRoles.test.js`; two by name, the rest as *+N weitere* with a tooltip) and *Bot kann vergeben* with the reason (`assign.reason`: `everyone`, `managed`, `botRole`, `noManageRoles`, `above` — via `memberRoles.roleBelowBot`, i.e. `comparePositionTo`). `hints` mark what to look at: `empty` (nobody has it), `sensitive` (only an *unusual* one, see below), `aboveBot` (a role the bot hands out sits above it; for a roster only its member/trial roles count, not former/staff). Permission aliases (`ManageEmojisAndStickers` = `ManageGuildExpressions`) count once; the bot's own role is always `botRole`, never `managed`. **Damping:** a sensitive permission that @everyone has, or that at least three other roles and more than half of them have, is *common* (`commonSensitive` of the list, `unusual` per role = the rest): the table shows it grey and names it once in a calm line above the table ("Üblich auf diesem Server, daher grau: … (17 von 19 Rollen)"); orange stays for the outliers, which come first in the cell. Red only where the bot should act but cannot (`aboveBot`, `noManageRoles`). Sorted by position, a **divider row** sits at the bot's role (its text sticks to the left while the table scrolls) — every other sort drops it and marks the bot's role with a small *Bot-Rolle* tag instead. *Nur Rollen mit Hinweis* is a switch. **Phone (≤ 600 px):** the uses and sensitive columns are hidden (uses already ≤ 900 px); a small second line under the name carries the meaning and the outliers (orange), *Bot kann vergeben* is one word (`assignShort`, full text as tooltip), members only the number, the divider the short text; the drawer is a bottom sheet over a dimmed backdrop that closes on a tap. A row opens **`ServerRoleDrawer.tsx`** (`GET /api/discord/roles/detail?guildId=&roleId=`, 404 `not_found` = "gone"): facts (rank as in the table, where it stands to the bot read from `assign`), permissions grouped like Discord's role editor (`groupPermissions`; only the set ones unless *Alle Rechte zeigen*, "x von N gesetzt"), the channel overwrites for this role (allow green, deny red) and the members with avatars and a search (from nine members, sixty shown; for @everyone the server sends the first 200 and `membersTotal`, the drawer says so). Creating, moving and editing roles stays in Discord. Tests: `test/services/discord/serverRoles.test.js`, `test/web/apiRoutes/discordRoles.test.js`, `ServerRolesPage.test.tsx`, `lib/discord/__tests__/serverRoles.test.ts`. A member's name in the drawer links to it on the member page (`/channels/members?user=<id>`, `&guild=<id>` on any server but the first). The open role is in the URL (`?role=<id>`, `&guild=<id>`), so a link opens it; the drawer's heading takes the role colour (`lib/discord/roleColor.ts`, a light and a dark variant for the two themes).
- **Mitglieder (`pages/channels/MembersPage.tsx`, display only).** Every member of the picked server from `GET /api/discord/members?guildId=` (`src/services/discord/serverMembers.js` → `apiRoutes/discordMembers.js`, area `channels` read; head as on the roles page, `membersError` when the GuildMembers fetch failed): avatar and name (Discord name beside it), the roles in their role colour, highest first (three, then *+N* with the rest as tooltip), *beigetreten* (short date) and the roster column — the roster with the character of its version in class colour, else the character (*nicht im Roster*), else *kein Charakter verknüpft*. Orange only for `missingRosters`: the member holds a roster's member or trial role without being in that roster. Roster ties come from **`src/services/discord/memberRelation.js`** (`relationOf(userId)` for one account — the Discord overview's join/leave list uses it, contract unchanged —, `relationIndex()` reads the roster, character and profile stores once for a whole server). Filters (`lib/discord/members.ts`): search (name, Discord name, characters), one role select, the switches *ohne Rolle*, *nicht im Roster* (never a bot) and *Bots ausblenden* (on by default), each with its count; columns sort with `useTableSort`; 50 rows, then *N weitere · alle zeigen*. **Phone (≤ 600 px):** roles, join date and roster columns go (the date already ≤ 900 px), a small second line under the name carries roster/character and the highest role. A row (or `?user=<id>`, also from the role drawer) opens **`MemberDrawer.tsx`** (`GET /api/discord/members/detail?guildId=&userId=`, 404 `not_found` or `gone: true` = "gone"; bottom sheet on a phone): its roles, its characters by version with the rosters each one actually stands in (`rosterIds` per character from `memberRelation.js`; the roster column likewise takes the character that is in the roster, not just the first of its version), and the channels it can see by category (`visibleChannels()` — `permissionsFor(member).has(ViewChannel)`, "x von N Kanälen", categories fold; names exactly as in Discord, decorations like `╭ ・` or emojis included). Roles and channels are changed in Discord. **Drawers on both pages and the URL:** opening one pushes a history step (`?user=` / `?role=`), so the browser's back button closes it; Esc, the close button and switching the server replace the entry instead of adding one. Without a configured server no drawer opens. Known gap: the page behind an open drawer still scrolls (no body scroll lock — there is no shared drawer component yet to put it in).
